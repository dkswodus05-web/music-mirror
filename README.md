# 🪞 Music Mirror — 지금 내 모습으로 만드는 국내 노래 플레이리스트

> 웹캠으로 내 모습을 3초 동안 **정밀 측정**하면, AI DJ가 표정·옷차림·분위기를 읽고 **어울리는 국내 대표곡 1곡 + 비슷한 노래 5곡**으로 **플레이리스트를 만들어 그 자리에서 유튜브로 이어서 틀어주는** 멀티모달 AI 웹 서비스

<br>

## 1. 프로젝트 개요

### 왜 만들었나
- 노래를 고를 때 "지금 기분에 맞는 노래"를 찾는 데 생각보다 시간이 오래 걸린다.
- 내 기분을 말로 설명하지 않아도 **카메라에 비친 모습만으로** AI가 분위기를 읽고 노래를 골라 주면 좋겠다는 아이디어에서 시작했다.
- 수업에서 배운 LLM 기술(멀티모달, 프롬프트 엔지니어링, Function Calling, MCP, TTS, 이미지 생성)과 컴퓨터 비전을 **하나의 서비스 흐름 안에서 연결**해 보는 것이 목표다.

### 무엇을 하나
| 단계 | 내용 |
|---|---|
| 🙂 얼굴 인식 | 브라우저에서 실시간으로 얼굴 수와 표정 7가지(행복·슬픔·화남·놀람·무표정·긴장·언짢음)를 인식. **한 명일 때만** 촬영 가능 |
| 📏 정밀 측정 | 카운트다운 3초 동안 **여러 프레임을 평균**해서 표정 확률, 얼굴 랜드마크 68점 기반 **미소 강도·입 벌림·눈 크기·눈썹 올림·고개 기울기/방향**, **화면 밝기**, **옷 주요색 3개(k-means)** 를 수치로 측정 |
| 🧠 분석 | gpt-4o-mini가 사진 + 측정값을 함께 보고 분위기를 한 줄로 정의 |
| 💡 대표곡 고르기 | AI가 분위기에 맞는 **국내곡** 후보 3곡을 떠올리고, 검색으로 확인한 뒤 가장 어울리는 **대표곡 1곡**을 고름 (정해진 목록 없음, 곡 제한 없음) |
| 🎶 플레이리스트 | 대표곡과 **분위기·템포·장르·감성이 비슷한 국내곡 5곡**을 AI가 골라 플레이리스트 완성. 곡마다 "대표곡과 비슷한 점"을 한 줄로 표시 |
| 🔍 검색 확인 | 6곡 모두 `search_youtube` 도구로 "가수 곡명"을 검색해 **실제로 있는 곡인지 확인** (6곡 병렬 검색) |
| 🧠 추천 근거 | **"왜 이 대표곡일까?"** 카드: 👀 사진·측정값 근거 → 🎭 분위기 판단 → 🎵 대표곡이 맞는 이유 → ⚖️ 다른 후보 대신 고른 이유 + 어울림 점수 |
| ▶ 재생 | 페이지 안에서 플레이리스트가 **이어서 재생**되고, 곡을 눌러 바로 들을 수 있음. 퍼가기 막힌 영상이면 같은 곡의 다른 영상 → 다음 곡으로 자동 전환. **유튜브 재생목록으로 열기** 버튼도 제공 |
| 🎙 DJ 멘트 | DJ 멘트를 음성(TTS)으로 읽어 줌 |
| 🔄 후속 요청 | "다른 곡으로", "더 신나게", "발라드 위주로", "밴드·인디", "아이돌" 같은 요청을 이전 대화를 기억한 채로 반영해 플레이리스트를 새로 만듦 |
| 🔁 반복 방지 | 최근 플레이리스트에 넣은 60곡은 다시 나오지 않게 제외 |
| 🎨 앨범 커버 | 오늘의 무드에 맞는 앨범 커버 이미지를 생성 |
| ⚙️ AI 설정 | 페이지에서 바로 API 키 입력, 모델 변경, 추천 기록 초기화 |

## 2. 시스템 구조

```
┌──────────────────────────┐   사진 + 정밀 측정값    ┌──────────────────────────────────┐
│  브라우저 (index.html)     │ ─────────────────────▶ │   Flask 서버 (app.py)              │
│  - 웹캠 / face-api 측정    │                        │  ① Responses API 호출 (멀티모달)    │
│    (얼굴 수·표정·랜드마크)  │ ◀───────────────────── │  ② function_call 받으면 실행        │
│  - 결과 / 유튜브 재생       │   JSON / mp3 / 이미지   │  ③ 결과 돌려주고 최종 답 받기        │
│  - AI 과정 시각화          │                        │  ④ 영상 ID·제목 검증                │
└──────────────────────────┘                        └───────┬────────────────┬─────────┘
                                                            │                │
                                          ┌─────────────────▼──┐   ┌─────────▼──────────┐
                                          │ youtube.py          │   │ OpenAI              │
                                          │ 유튜브 검색 결과에서   │   │ - gpt-4o-mini       │
                                          │ 영상 제목·채널·길이·   │   │ - gpt-4o-mini-tts   │
                                          │ 조회수·영상 ID 추출   │   │ - gpt-image-1-mini  │
                                          └────────────────────┘   └────────────────────┘
              mcp_server.py : 같은 유튜브 검색 도구를 MCP 도구로도 공개 (다른 AI 앱에서 사용 가능)
```

### 추천 1회가 처리되는 순서
1. 브라우저가 face-api로 3초 동안 얼굴을 측정해서 **딱 한 명**인지 확인하고, 표정·랜드마크 수치·밝기·옷 색을 평균 낸 뒤 사진과 함께 `/api/recommend`로 보낸다.
2. 서버가 **시스템 프롬프트 + 사진 + 측정값 + 조건(국내곡, 대표곡 1 + 비슷한 곡 5) + 최근 추천곡 목록 + 도구 목록**을 Responses API에 보낸다.
3. 모델이 분위기를 판단하고 대표곡 후보를 떠올려 `search_youtube("DAY6 한 페이지가 될 수 있게")`처럼 **도구 호출을 요청**한다. 대표곡을 정한 뒤 비슷한 곡 5곡도 같은 방법으로 확인한다. (여러 곡을 한 번에 병렬로 호출)
4. 서버가 유튜브 검색을 **동시에(병렬)** 실행해 영상 정보(제목·채널·길이·조회수·영상 ID)를 `function_call_output`으로 돌려준다. 모음집·플레이리스트·라이브 방송·최근 추천곡 영상은 자동으로 뺀다.
5. 모델이 JSON Schema에 맞춰 최종 답(대표곡, 플레이리스트 5곡과 각각의 비슷한 점, 플레이리스트 제목, 근거·분위기·비교·점수)을 만든다. 사진 속 사람 수(`person_count`)도 함께 답하게 해서, 1명이 아니면 서버가 다시 찍어 달라고 돌려보낸다 (얼굴 수 이중 확인).
6. 서버가 **6곡 모두 검증**한다: AI가 적은 영상 ID가 **실제 검색 결과에 있었고, 영상 제목에 곡명이 들어 있는지** 확인한다. 통과하면 "✓ 실제 영상 확인" 배지가 붙고, 통과 못 한 곡은 실제 검색으로 재생할 영상을 다시 찾는다. 대표곡과 같은 곡이 플레이리스트에 또 있으면 뺀다.
7. 브라우저가 결과, 추론 과정(CoT), 도구 호출 기록, 토큰 사용량을 화면에 보여준다.

## 3. 사용 기술 (수업 내용 ↔ 프로젝트 적용)

| 수업에서 배운 것 | 프로젝트에서 어떻게 썼나 | 코드 위치 |
|---|---|---|
| **OpenAI Responses API** | `client.responses.create(instructions=..., input=...)`로 모든 대화 처리 | `app.py` |
| **멀티모달 입력** | 웹캠 사진을 `input_image`로 넣어 모델이 직접 보고 판단 | `app.py` |
| **컴퓨터 비전 (얼굴·표정 정밀 측정)** | face-api(TinyFaceDetector + FaceLandmark68Tiny + FaceExpressionNet)로 얼굴 수·표정 확률·랜드마크 68점을 다중 프레임 측정. 랜드마크로 미소(입 너비·입꼬리), 입 벌림, 눈 크기(EAR), 눈썹 높이, 고개 기울기를 계산하고 옷 색은 k-means로 3색 추출 | `templates/index.html`, `static/face-api/` |
| **프롬프트 엔지니어링 – 역할 부여** | "감성 라디오 DJ 미러" 페르소나 | `prompts.py` |
| **Few-shot** | 좋은 추천 예시(관찰 → 대표곡 후보 → 검색 확인 → 비슷한 곡 플레이리스트)를 프롬프트에 포함 | `prompts.py` |
| **Counter-example** | 나쁜 예시 7개(이유 없음, 검색 없이 지어낸 곡, 외모 평가, 분위기가 섞인 플레이리스트, 막연한 "비슷한 느낌", 같은 가수 몰아넣기, 해외곡 넣기)를 주고 피하게 함 | `prompts.py` |
| **CoT (단계별 추론)** | 관찰 → 분위기 판단 → 대표곡 후보 → 대표곡 확인 → 비슷한 곡 플레이리스트 → 설명 6단계로 생각하게 하고, `thinking`과 `why`(근거·분위기 연결·곡 매칭·후보 비교·점수)를 화면에 표시 | `prompts.py`, `index.html` |
| **Structured Outputs** | `text.format = json_schema`로 항상 같은 JSON 형태를 받음 | `prompts.py` |
| **Function Calling** | `search_youtube` 도구 정의 → `function_call` 실행 → `function_call_output` 반환 루프. 한 번에 여러 곡을 호출하면 서버가 `ThreadPoolExecutor`로 동시에 검색 | `prompts.py`, `app.py` |
| **외부 데이터 검색 도구** | 유튜브 검색 결과 페이지(ytInitialData)를 파싱해 영상 정보를 가져오는 도구. API 키 없이, 곡 제한 없이 검색 | `youtube.py` |
| **멀티턴 대화** | `store=True` + `previous_response_id`로 이전 대화를 기억 ("발라드 위주로 바꿔줘") | `app.py` |
| **Hallucination 방지** | ① 검색으로 확인한 곡만 넣게 지시 ② 6곡 모두 영상 ID가 실제 검색 결과에 있었는지 + 제목에 곡명이 있는지 서버에서 검증 ③ 곡마다 검증 결과를 배지로 표시 | `app.py`, `youtube.py` |
| **MCP (FastMCP)** | `search_youtube`, `youtube_link`, `find_youtube_video`를 MCP 서버 도구로 공개 + 클라이언트 테스트 | `mcp_server.py`, `mcp_client.py` |
| **TTS** | DJ 멘트를 `gpt-4o-mini-tts`로 읽어 줌 (`instructions`로 말투 지정) | `app.py` |
| **이미지 생성** | 오늘의 무드 앨범 커버를 `gpt-image-1-mini`로 생성 | `app.py` |
| **.env / 키 관리** | API 키는 `.env` 또는 페이지 설정으로 입력. 서버 메모리에만 두고 브라우저 저장소나 파일에 남기지 않음. 예시 문구나 한글이 섞인 키는 실행 시 걸러냄 | `app.py` |

## 5. 설치 및 실행

### ① 설치
```bash
# (권장) 가상환경
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Mac / Linux

pip install -r requirements.txt
```

### ② API 키 설정
방법 A) 실행 후 페이지 오른쪽 위 **⚙️ AI 설정**에서 키를 넣고 모델을 고른다. (서버를 껐다 켜면 다시 넣어야 함)

방법 B) `.env.example`을 복사해서 `.env`로 이름을 바꾸고 `OPENAI_API_KEY=` 뒤에 실제 키를 넣는다.
- Windows에서 `.env.txt`가 되지 않게 주의
- 예시 문구 `sk-여기에_키_입력`을 그대로 두면 데모 모드로 실행된다

> 키가 없으면 **데모 모드**로 동작한다. 표정으로 분위기 검색어를 만들어 유튜브 검색 결과로 플레이리스트를 채운다. (AI 판단 없음, 곡 선택이 거칠다)

## 6. 사용 방법

1. (키가 없으면) **⚙️ AI 설정**에서 API 키 입력, 모델 선택
2. **카메라 켜기** → 브라우저의 카메라 권한 허용
3. 얼굴에 보라색 박스와 랜드마크 점이 생기고, 왼쪽 위에 실시간 표정(예: 😄 행복 87%), 오른쪽 아래에 표정·미소·눈 크기·입 벌림 막대가 나온다. 두 명 이상이면 빨간 박스와 경고가 뜨고 버튼이 잠긴다
4. **✨ 내 모습으로 플레이리스트 만들기** → 3초 카운트다운 동안 정밀 측정 후 촬영
5. 분석 결과(분위기, 표정, 옷, 키워드)와 **플레이리스트(★ 대표곡 + 비슷한 곡 5곡)** 가 나온다
6. 가운데 **▶ 버튼** 또는 **▶ 전체 재생**을 누르면 플레이리스트가 이어서 재생된다. 곡 옆 ▶로 원하는 곡부터 듣거나, **↗ 유튜브 재생목록**으로 유튜브에서 열 수 있다
7. **🧠 왜 이 대표곡일까?** 카드에서 추천 근거, **📏 정밀 측정 리포트**에서 측정 수치를 확인
8. DJ 멘트가 음성으로 나온다 (다시 들으려면 DJ 멘트 옆 ▶)
9. 아래 버튼으로 **🔄 다른 곡으로 / 🔥 더 신나게 / 🌙 더 잔잔하게 / 🎤 발라드 / 🎸 밴드·인디 / 💃 아이돌** 요청, 또는 직접 입력 (예: "90년대 감성으로")
10. **🎨 앨범커버 만들기**로 오늘의 무드 이미지 생성
11. 화면 아래 **🧠 AI가 고른 과정**에서 단계별 추론, 유튜브 검색 기록, 사용된 기술, 토큰 사용량을 확인

### 튜닝 포인트 (`app.py` 상단)
```python
TEMPERATURE = 0.9      # 높을수록 다양한 곡을 떠올림
YT_RESULTS = 5         # search_youtube 한 번에 돌려줄 영상 수
MAX_TOOL_ROUNDS = 8    # 도구 호출 반복 최대 횟수 (플레이리스트 6곡 확인)
RECENT_LIMIT = 60      # 최근 추천곡 몇 곡까지 다시 안 나오게 할지
TTS_VOICE = "coral"    # DJ 목소리
```
플레이리스트 곡 수는 `prompts.py`의 `PLAYLIST_EXTRA`(기본 5)로 바꾼다.
얼굴 인식 감도는 `templates/index.html`의 `FACE_INPUT`, `FACE_MIN_SCORE`에서 조정한다.

## 7. 한계와 개선 방안

| 현재 한계 | 개선 방안 |
|---|---|
| 유튜브 검색은 검색 페이지 구조가 바뀌면 깨질 수 있다 | YouTube Data API로 교체 (퍼가기 가능한 영상만 검색도 가능) |
| 곡 후보를 AI의 기억에서 떠올리므로 아주 최신곡은 잘 모른다 | 멜론·벅스 차트를 도구로 추가해 최신곡 후보 제공 |
| "비슷한 곡"을 AI의 음악 지식으로 판단한다 | 음원의 템포·키·에너지 같은 오디오 특징을 비교하는 유사도 측정 추가 |
| 퍼가기가 막힌 공식 MV는 재생이 안 될 수 있다 (현재는 같은 곡의 다른 영상 → 다음 곡으로 자동 전환) | Spotify·멜론 재생 연동 |
| 조명이 어둡거나 고개를 많이 돌리면 측정 정확도가 떨어진다 | 조명 보정, 정면 유도 안내 |
| 측정 수치의 기준값(보통 미소 폭 등)을 일반값으로 정했다 | 처음에 무표정을 한 번 찍어 개인 기준값을 잡는 캘리브레이션 |
| 데모 모드는 AI 판단 없이 분위기 검색어로만 고른다 | 로컬 소형 모델(예: Qwen)로 오프라인 추천 |
| 사용자 취향을 기억하지 못한다 | 곡마다 좋아요/싫어요를 받아 다음 플레이리스트에 반영 |
| 날씨·시간 같은 상황을 모른다 | 수업의 날씨 API(Open-Meteo)를 도구로 추가해 "비 오는 저녁" 같은 상황까지 반영 |
| 플레이리스트 6곡을 만들고 검증하는 데 10~20초가 걸린다 | 스트리밍으로 대표곡부터 먼저 보여주기, 검색 결과 캐싱 |
| 로컬에서만 동작한다 | Render / Hugging Face Spaces 배포, 키는 서버 환경변수로 관리 |

## 8. 개인정보 및 안전
- 촬영한 사진은 분석 요청에만 쓰이고 서버에 저장하지 않는다. 얼굴 측정은 브라우저 안에서만 이루어진다.
- 프롬프트에서 외모 평가와 나이·인종·체형 같은 민감한 특성 추측을 금지하고, 표정·옷·분위기만 다루게 했다.
- API 키는 `.env`에만 두고 `.gitignore`로 GitHub에 올라가지 않게 했다.
